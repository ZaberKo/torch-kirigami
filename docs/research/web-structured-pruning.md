# 原生搜索：结构化剪枝流程与 API 设计依据

调研日期：2026-09-06。范围是可物理缩小稠密模型的结构化剪枝；不重新讨论 FX 捕获，不把 N:M 稀疏、动态 token 跳过或任意模型重写当成相同能力。以下区分论文事实和本库设计建议；这是设计讨论材料，尚未实现 API。

## 结论

“选择一个起点，由依赖图找出必须一起变化的位置”是通用剪枝的重要基础，但还不足以决定怎么剪。完整过程至少还要回答：哪些起点可选，怎么测量重要性，哪些分数可以比较，怎样满足预算和分组约束，以及怎样实际修改和恢复模型。

建议的公共流程是：

```text
构造候选结构
    → 查询依赖闭包与剩余约束
    → 收集方法需要的观测、估计重要性
    → 在比较范围和预算内联合选择
    → 一次传播完整请求、检查结构与执行能力
    → 生成并应用修改计划
    → 按需恢复训练或补偿、重新建图
```

这是一条统一的用户流程。内部允许简单排序策略与联合优化策略复用相同的候选、依赖分析、预算报告和执行能力，不要求所有算法都输出一个静态分数数组。

## 代表工作告诉我们的事实

| 工作及原始来源 | 核心机制 | 对接口的直接启发 |
| --- | --- | --- |
| [DepGraph，CVPR 2023](https://openaccess.thecvf.com/content/CVPR2023/html/Fang_DepGraph_Towards_Any_Structural_Pruning_CVPR_2023_paper.html) | 自动发现耦合结构；实验中简单范数准则也可用于跨架构剪枝。 | 依赖分析负责联动合法性，重要性不应成为依赖规则。 |
| [Isomorphic Pruning，ECCV 2024](https://arxiv.org/abs/2407.04616) | 先对耦合子结构聚合重要性，再在同构结构集合内分别排序，缓解异构结构直接比较的问题。 | “成员聚合”和“在哪些候选之间排名”是不同职责；比较范围应能扩展。 |
| [Importance Estimation for Neural Network Pruning，CVPR 2019](https://arxiv.org/abs/1906.10771) | 用一阶、二阶 Taylor 近似估计删除结构对损失的影响，并迭代删除。 | 梯度并非一个统一的 metric；估计对象、统计单位和归约顺序必须明确。 |
| [Group Fisher Pruning，ICML 2021](https://proceedings.mlr.press/v139/liu21ab.html) | 耦合通道共享 mask，通过共享 mask 的梯度计算重要性，并考虑 memory reduction。 | 联动组分数可能含交叉项；代价模型独立于重要性，并明确代理指标。 |
| [ThiNet，ICCV 2017](https://openaccess.thecvf.com/content_iccv_2017/html/Luo_ThiNet_A_Filter_ICCV_2017_paper.html) | 根据下一层的响应统计进行通道选择，包含贪心选择及重建。 | 观测不限于参数；删除集合与重建效果有关，需容纳联合选择和权重修复。 |
| [Network Slimming，ICCV 2017](https://arxiv.org/abs/1708.06519) | 训练期间对通道缩放因子施加稀疏约束，再剪除通道，可多轮执行。 | 稀疏训练不是换一个 score；正则化与训练生命周期要留在训练适配层。 |
| [LLM-Pruner，NeurIPS 2023](https://arxiv.org/abs/2305.11627) | 发现耦合结构，依据梯度信息删除，之后通过 LoRA 恢复能力。 | “发现—估计—恢复”可共用框架，任务损失、校准数据和恢复训练由外部提供。 |
| [Diff-Pruning，NeurIPS 2023](https://arxiv.org/abs/2305.10924) | 筛选有贡献的 diffusion timesteps，并组合其梯度进行 Taylor 重要性估计。 | 统计轴可能是样本、token、时间步或任务；不能在核心写死分类 loss 与 batch 平均。 |
| [SliceGPT，ICLR 2024](https://arxiv.org/abs/2401.15024) | 利用 Transformer 的计算不变性先做正交变换，再删除低重要性方向对应的行列。 | 改变基底不能仅用原坐标上的删除集合表达；应作为显式模型变换阶段，变换后重新分析。 |
| [Adapt-Pruner，2025 预印本](https://arxiv.org/abs/2502.03460) | 根据层的输入输出相似度分配剪枝强度，再剪内部结构；增量剪枝与训练交替。 | 预算分配、结构内排序及多轮调度可由不同信号驱动；每轮可能需要重新观测。 |

这些工作并没有证明存在一个对所有结构、任务、硬件都最优的默认 metric；本表用于确定扩展边界，不用于比较不同实验条件下的精度排行榜。

## 为什么不能把所有方法都压成静态 score

### 联动组的重要性并不总是成员分数的求和

Magnitude 可以把唯一参数区域中的元素绝对值求和，或者计算明确约定的 L2 范数；使用均值则又定义了另一种偏好。它们是可实现的基础启发式，不能混用名字。

对于 Taylor，“先将权重乘梯度求和再取绝对值”和“先逐元素取绝对值再求和”不是同一个量：

```text
abs(sum(w * grad)) != sum(abs(w * grad))
```

同样，Group Fisher 的式 (4) 对每个样本先累加耦合通道的 mask 梯度，再平方，最后跨样本累加：

```text
score(group) ∝ sum_over_samples(
    sum_over_coupled_members(mask_gradient(sample, member)) ** 2
)
```

因此，各成员已平方的 score 无法一般性恢复组的交叉项；把 batch 平均梯度再平方也不等于逐样本平方后平均。引用依据：[Group Fisher 正文，式 (4)](https://proceedings.mlr.press/v139/liu21ab/liu21ab.pdf)。

建议：基础 estimator 可以复用 region reduction 和 sum/mean 等工具，但完整 estimator 有权直接读取组级观测。不要强制所有 estimator 先输出每个参数的独立标量，再交给一个通用 reducer。

### 有的方法同时决定删除位置和剩余权重

ThiNet 类重建方法关心一组通道共同造成的响应误差，不能仅凭每个通道独立的静态排名恢复完整算法。[ThiNet 正文](https://openaccess.thecvf.com/content_ICCV_2017/papers/Luo_ThiNet_A_Filter_ICCV_2017_paper.pdf)

二阶 OBS/OBC 类方法还会在删除后修正保留权重，后续选择随之改变。这里参考 OBC 是为了识别接口边界；OBC 原论文主要验证非结构化、块和 N:M 剪枝，不能据此声称它实现了通用通道剪枝。[OBC 正文，第 3–4 节与结论](https://arxiv.org/pdf/2208.11580)

建议：通用策略接口返回一份提案，提案可以附带明确的补偿要求；物理执行仍由单独模块检查和实施。默认 magnitude/Taylor 策略只需要删除和紧凑化。首版不需要实现 OBC，也不需要为它预造一个优化器框架。

### 还有方法需要训练或改变表示

Network Slimming 需要在训练中塑造缩放因子；SliceGPT 需要做正交变换。二者都不能仅通过替换 `importance(...)` 完整实现。建议保留明确的训练适配和模型变换入口；它们不能静默夹在依赖传播中。模型结构或坐标系改变后，候选、依赖图和统计都需重新绑定。

## 面向本库的最小接口拆分建议

以下名称是职责草案，不是已确定的导出 API。

| 职责 | 输入与输出 | 必须明确的契约 |
| --- | --- | --- |
| Candidate / PruningSpace | 候选起点或起点集合 → 依赖闭包、约束、结构标签 | 起点是结构位置，不只是 module/node；候选不保证独自可行。 |
| ImportanceEstimator | 候选、参数、可选观测 → 带候选 ID 的分数及统计说明 | 越大是否越重要；观测单位、取绝对值/平方的时机、归约方式；缺少数据时报错。 |
| Policy | 候选空间、目标、预算、分析上下文 → Proposal | 可实现排序，也可实现联合或有状态优化；最终提交完整删除请求。 |
| Cost / Budget | 联合 Impact → 预计资源变化及预算是否满足 | 通道比例、参数量、MACs、延迟目标不能共用含糊的一个 ratio。 |
| Executor | graph + resolved Impact + 支持的修改要求 → 可审查的 EditPlan → 应用结果 | 所有属性、布局、尺寸修改必须有执行支持；失败前不留下半修改模型。 |
| Session / 外部训练适配 | 观测、剪枝轮次、恢复调用、重建 | 不接管用户训练框架；生命周期、统计清理、参数替换映射和失效条件明确。 |

普通用户可以使用一个高层入口配好这些默认组件；用户不需要手工拼六个对象。只有替换算法的人才使用对应接口。

### 候选与闭包

- 默认可从 Conv/Linear 的输出通道生成候选，但扩展要接受任意结构选择或多个 seed；attention head、成块维度、固定 groups 约束不是同一个概念。
- 不同 seed 可能得到同一个完整变化，应规范化去重；只有部分参数区域重叠时，不能因此把两个候选永久合并。
- 某候选单独触发“各组保留数量不相等”时，可能能与另一个候选组成合法请求。依赖层继续报告约束，选择策略负责联合补全，不能过滤所有单独 unresolved 的候选。
- 联合选择完成后重新执行一次 `propagate(remove=all_seeds)`。不能把多个独立 Impact 简单拼接便宣布合法。

### 观测和分数

- 参数 metric 按原始参数对象及选择区域去重，避免别名、多路径或共享调用重复计权。
- 激活 metric 的观测对象是调用点/值，可能需要跨调用汇总；它与共享参数的物理存储去重是两件事。
- 观测声明区分无需数据、forward 统计、loss/backward 统计、逐样本梯度。采集后尽量保留累计统计，释放激活和 hooks。
- loss、数据遍历、混合精度、分布式同步交给调用方适配；首版读取现有 `Parameter.grad` 的 Taylor estimator 应清楚写明，它不自动等于逐样本 Fisher。
- 图的结构缓存可能仍有效，但训练会改变 magnitude/Taylor 分数。评分结果和观测有独立的轮次/快照有效性，不能直接复用依赖图“不因普通训练而失效”的规则。

### 排序范围与预算

局部、全局和同构域内排名是可比较范围与预算分配的选择，不能默认“全局一定更好”。Isomorphic Pruning 属于这一层，不需要改变现有依赖求解器。[Isomorphic Pruning 正文，第 3.3 节](https://arxiv.org/html/2407.04616v1)

预算必须定义分母和基线：某个结构域的通道比例、全模型唯一参数数量、给定输入下的 MACs，分别计算。保留数的取整、非空和整除约束会使目标不可精确达到，结果应报告实际值和差距。

参数节省应对最终联合选择区域求并集；不能累加有重叠候选的单独成本。对 MACs/延迟，两个方向同时收窄同一矩阵时通常也不可简单相加。应支持基于当前联合提案重新估计边际成本。

Group Fisher 关于 memory reduction 与 GPU 加速的关系是其模型和测量环境下的经验结果，不是所有现代 GPU 上的定律。延迟必须绑定硬件、输入形状、dtype 和测量协议；首版可以暂不提供自动延迟优化。[Group Fisher 正文，第 3.3 节](https://proceedings.mlr.press/v139/liu21ab/liu21ab.pdf)

## 建议首版落实范围

先讨论确认接口，再实现以下闭环：

1. 手工结构请求与自动 Conv/Linear 通道候选。
2. L1/L2 magnitude；一个定义清楚的权重一阶 Taylor 基线；自定义 estimator。
3. 局部预算和显式全局域下的基础选择策略，处理非空、整除、分组平衡和候选重叠；无法处理的约束明确停止。
4. 将联合 Impact 编译为修改计划，与依赖分析模块分开。基础物理切片、属性更新、别名保持，输出参数替换及坐标映射。
5. 用户显式驱动一轮或多轮剪枝，恢复训练后重新评分，结构改变后重建。

保留组级统计、联合策略、比较域、补偿和训练适配的接口即可；不在首版实现 Fisher、重建优化、正交变换、自动任务训练器或硬件搜索器。扩展性来自清楚的对象与有效性契约，而不是先加入大量抽象层。
